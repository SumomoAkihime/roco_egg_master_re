## 如何导入 **已核实的** S5 原始数据

准备本仓库 `database/*.json` 使用的**原生结构**（注意：这不是 091p、BWIKI 或 roco-showdown 的 API 格式）：

```json
{
  "season": "S5",
  "records": [
    {
      "id": 999999,
      "name": "示例精灵（请替换成已核实数据）",
      "avatar": "999999-示例精灵.png",
      "egg_groups": ["动物组"],
      "egg_data": { "has_egg": true, "egg_groups": ["动物组"] },
      "evolution_chain": ["示例精灵（请替换成已核实数据）"],
      "types": ["普通"],
      "regional_forms": [],
      "lord_forms": [],
      "other_forms": []
    }
  ]
}
```

上面**仅是格式示例，不是真实精灵数据**。校验不等于数据真实性；必须先通过权威来源和游戏实测核对 ID、蛋组、进化关系、可繁育状态、形态。

```powershell
node scripts/import-season-data.cjs --file .\verified-s5.json --season S5
node scripts/import-season-data.cjs --file .\verified-s5.json --season S5 --apply
npm run build
```

注意：`npm run build` 会将 `database/` 中的 JSON 合并到 `src/pets_data.json`；它不会下载最新赛季资料。
原项目也依赖 `高清精灵头像/` 目录，缺少新头像时应新增占位图片或补齐对应资源，而非随意复用其他精灵图片。

### 数据审查要求

1. **原生 database 的 id 是项目的图鉴条目 ID，不是游戏封包里的 config_id，更不是实例 GID**。不同来源的编号命名空间必须先做名称/形态对照，绝不可直接把 API 中的 3001 等字段写成原生 id。
   导入脚本现在会拒绝同名不同 ID，减少意外生成重复精灵。
2. 分清「可出现异色」与「**用户实际拥有异色**」，前者属于图鉴，后者属于抓包/人工标记。
3. 同一只精灵可能有多个可育形态；赛季规则和特殊例外需要专门核实。
4. 确认 S5 首批与后续增量更新数据后，再把发布状态从“开发预览”改为“已覆盖 S5”。
5. `database-backups/` 和 `roco_egg_data.json` 需保留备份；不得以新图鉴覆盖玩家已有数据。

## 先拉取公开图鉴作为待审核候选

在 Windows Node.js 22+ 环境运行：

```powershell
node scripts/fetch-public-catalog.cjs
```

它仅通过 [091p 公开只读 API](https://091p.com/lkwg/api.html?resource=pets) 拉取分页快照，并保存至未纳入 Git 的 `data-candidates/091p-pets-unverified.json`。文件会带来源、更新时间和 S5 时效性提示。**不会改动 database 或正式图鉴**；第二条命令生成 `data-candidates/catalog-review.csv` 与 JSON，列出本地图鉴缺失候选、ID/名称冲突。由于不同网站的条目数量与 ID 命名空间有差异，必须经过人工/游戏配置核对才能转换。

## 本机助手 API 一键导入（Windows）

在「父母本管理中心」打开「从游戏导入数据」，切换「助手 API 直连」。启动本机 [rocom-helper](https://github.com/h3110w0r1d-y/rocom-helper)，开启实际网卡监听并进入游戏，在游戏里打开宠物箱/仓库，然后点「刷新角色」→选择 UID→「读取仓库」。

此功能仅访问 `http://127.0.0.1:4939/api/users`、`/api/pet-info`、`/api/box-info`，从后两者把宠物实例 GID 和仓库格位关联，随后仍使用原项目的「导入所选精灵」逻辑。本地助手若无法识别 S5 的新封包，此功能也不能自行解码；需要升级助手协议。开发者目前没有在实际 S5 游戏客户端验证该链路。

**安全提醒**：rocom-helper 项目特别提醒 Windows 本机直接网卡抓包可能存在游戏封号风险；使用前请自行确认游戏条款并评估风险。不会要求提供账号密码，且不应把含 UID、IP、GID 的原始封包或日志上传公开仓库。


### 已验证的导入字段边界

- **形态识别**：游戏 `base_conf_id` 指当前进化形态，`conf_id` 往往指家族/原始形态。优先查 `base_conf_id`，只有缺映射时才回退 `conf_id`，绝不把游戏配置 ID 当图鉴编号。
- **实例唯一性**：`gid` 作为字符串存储；超出 JavaScript 安全整数范围的数字不能无损恢复，缺少可靠 GID 时使用属性指纹去重。
- **性别**：未知/无性别不再默认为母本；这类精灵不进入父母本仓库及异色配对。
- **来源可信度**：S5 480、486、489 的配置编号只保留候选字段，不参与自动品种匹配。未能匹配到本地图鉴的精灵会显示“图鉴待匹配”，默认不勾选。
- **异色状态**：未知与“已确认普通”不同；修改手动异色状态时记录人工核对标记。

## 当前算法限制

- 只用共同蛋组、现有已标记异色个体和性别生成**候选**配对。
- 对异色遗传方式、雄性传递概率、隔窝/串窝关系、产蛋次数、赛季限定机制均未进行游戏实测。
- “传递路线”是假定每一中间目标都能获得合适性别后代的**理论连通路径**，不是保证产出的路线。异色母体作为起点时，明确提示需要先获得同种异色公体。
- 目标精灵若可由当前已拥有的异色精灵直接进化获得，优先显示**无需再孵蛋的进化路线**；平行终极分支之间不会错误地互认进化。目标母本筛选也会考虑其进化家族，而不是只匹配当前阶段名字。
- 「共享公本」允许一个公本被用于多个目标的**逻辑规划**，不意味着游戏可同时将同一实例放入多个真实窝位。
- 同名/同属性但不同 GID 的实例作为不同精灵保留，同一 GID 在重复抓包分页内去重；仍需 S5 真实仓库验证。
